NICE NMF Integration Guide

แปลง NICE .nmf เป็น WAV ด้วย .NET SaveMgr Worker

เอกสารนี้อธิบายระบบแปลงไฟล์เสียง NICE .nmf เป็น PCM WAV สำหรับ browser player และการนำไปเชื่อมต่อกับระบบอื่น

x86 .NET Worker LocalPlaylist WaveController Browser WAV Queue
ระบบนี้ไม่ได้เขียน decoder ของ NICE เอง แต่เรียก flow export WAV ของ NICE Player ผ่าน DLL ของ NICE โดยตรง ดังนั้น server ต้องมี NICE Player Release 6 runtime ครบ

สรุปสั้น

  • Input: ไฟล์ NICE .nmf
  • Output: PCM WAV, 8000 Hz, mono, 16-bit โดยปกติ
  • Runtime: C:\Program Files (x86)\NICE Systems\NICE Player Release 6
  • Engine หลัก: NiceSaveMgrWorker.exe แบบ x86 .NET Framework
  • Production ไม่ scan timeline packet เพื่อความเร็ว
  • Debug เปิดด้วย ?debug=1

Flow การแปลงเสียง

Browser
  -> POST /api/convert?name=<file.nmf>&engine=dotnet
  -> server.py
  -> เขียน .nmf ลง temp folder
  -> ส่งงานเข้า SaveMgrWorker queue
  -> NiceSaveMgrWorker.exe โหลด NICE DLL แบบ x86
  -> LocalPlaylist + WaveController สร้าง WAV
  -> server.py อ่าน WAV + metadata
  -> ส่ง audio/wav กลับ browser
  -> app.js สร้าง audio object + waveform + timing detail

flow ภายใน NICE ที่ใช้:

LocalPlaylist.Load(input.nmf, true, false)
-> เลือก item แรกจาก playlist
-> item.OutputFileName = output.wav
-> WaveController.Init(item, -1, SaveMediaType.AllTypes)
-> WaveController.Save(null)
-> output WAV

อธิบาย code ทุกไฟล์

start_nmf_player.bat

เปิด web player แบบง่ายสำหรับผู้ใช้ทั่วไป โดยเข้า folder ที่ถูกต้องแล้วรัน server.py บน port ที่กำหนด เช่น 6797

nmf_web_player/server.py

Python HTTP server หลัก ทำหน้าที่ serve frontend, ตรวจ health, รับ upload .nmf, ส่งงานเข้า worker queue, อ่าน WAV metadata และส่ง audio/wav กลับ browser

  • SaveMgrWorker: เปิด NiceSaveMgrWorker.exe --worker ค้างไว้
  • lock: serialize conversion ให้ทำทีละงาน
  • nice_status(): ตรวจ runtime และ DLL
  • convert_nmf(): flow แปลงต่อ request
  • wav_peak(): ตรวจ peak แบบ sampling ใน production

nmf_web_player/index.html

โครงสร้างหน้า web player: ปุ่มเลือกไฟล์, runtime panel, file list, waveform, playback controls, timing modal และ <audio>

nmf_web_player/styles.css

กำหนด layout และ visual design ของ player รวมถึง sidebar, list, waveform, modal และ responsive behavior

nmf_web_player/app.js

logic ฝั่ง browser: ingest files, ส่ง POST /api/convert, อ่าน headers, เล่นเสียง, วาด waveform, sync seek bar, แสดง timing และเปิด debug mode เมื่อ URL มี ?debug=1

tools/NiceSaveMgrWorker.cs

source ของ x86 .NET worker ที่โหลด NICE DLL, ติดตั้ง AssemblyResolve, เรียก LocalPlaylist และ WaveController

stdin:
CONVERT<TAB><base64 input path><TAB><base64 output path>

stdout:
OK<TAB><elapsed ms><TAB><base64 output path>
ERR<TAB><elapsed ms><TAB><base64 error message>

tools/NiceSaveMgrWorker.exe

compiled worker ที่ server ใช้จริง ช่วยลด overhead เพราะไม่ต้องเปิด PowerShell และ compile C# ทุก request

tools/nice_nmf_to_wav.py

Python wrapper สำหรับแปลงนอกเว็บหรือ fallback path ถ้ามี worker exe จะใช้ exe ก่อน ถ้าไม่มีจะ fallback ไป PowerShell bridge

tools/try_nice_player_wave_convert.ps1

PowerShell bridge แบบเดิม ใช้ 32-bit PowerShell + Add-Type เพื่อ compile C# bridge ใน memory ยังเก็บไว้สำหรับ fallback/debug

tools/try_nice_nmf_convert.ps1 และ tools/NiceNmfConverter.cs

legacy experiment สำหรับ path MediaFileConverter.NmfToVox ไม่ใช่ production path เพราะบางไฟล์ output ไม่ตรงกับ manual Save WAV

เอกสาร .md และ .html

NICE_NMF_INTEGRATION_GUIDE.md สำหรับอ่านใน repo/editor และ NICE_NMF_INTEGRATION_GUIDE.html สำหรับเปิดอ่านใน browser

ความหมายของ timing

ค่าความหมาย
Convert timeเวลาใน worker ที่ NICE SaveMgr/WaveController ใช้สร้าง WAV จริง
Server timeเวลารวมฝั่ง server รวม upload/temp/queue/convert/read/metadata/peak
Browser timeเวลารวมฝั่ง browser ตั้งแต่อ่านไฟล์จนพร้อมเล่น
Queue waitเวลารอ worker ว่างเมื่อมีหลาย request
Start x86 .NET SaveMgr workerเกิดตอน request แรกหลังเปิด server หรือ worker restart
Sample WAV peakตรวจระดับเสียงแบบเร็วใน production
Scan NMF timeline packetsมีเฉพาะ ?debug=1

การนำไปพัฒนาต่อหรือเชื่อมต่อกับระบบอื่น

แนวทางที่แนะนำคือแยกเป็น conversion service แล้วให้ระบบอื่นเรียกผ่าน HTTP API:

ระบบหลัก -> POST .nmf -> NICE conversion service -> audio/wav -> ระบบหลัก/browser
  • ระบบหลักไม่ต้องโหลด NICE DLL เก่าโดยตรง
  • แยก dependency 32-bit ออกจาก backend หลัก
  • scale/monitor/retry แยกได้ง่าย
  • ควรมี auth, file size limit, timeout และ logging ก่อนเปิดให้หลายผู้ใช้

ถ้าจะเรียกจาก Python โดยตรง:

from pathlib import Path
from nice_nmf_to_wav import convert_file

convert_file(
    Path(r"C:\audio\input.nmf"),
    Path(r"C:\audio\output.wav"),
    engine="dotnet",
)

Checklist ก่อนส่งต่อระบบจริง

  • ติดตั้ง NICE Player Release 6 บน server
  • GET /api/health ได้ ok: true
  • saveMgrWorkerReady: true
  • DLL ทุกตัวใน requiredFiles เป็น exists: true
  • ทดสอบไฟล์เล็ก กลาง ใหญ่
  • เทียบ duration กับ NICE Player manual save
  • X-NMF-engine เป็น dotnet_save_mgr_worker
  • production ได้ X-NMF-timeline: skipped
  • เปิด ?debug=1 แล้ว timing detail แสดงครบ
  • ทดสอบ 2 request พร้อมกันและดู queue_wait
  • ตั้ง file size limit, timeout, auth และ logging ตามระบบจริง
